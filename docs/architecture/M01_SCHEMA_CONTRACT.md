# M01 canonical evidence and persistence contract

The implementation preserves the 34 preflight record types and adds **MotionTrack** as the thirty-fifth type. The Director approved this narrow extension during implementation because the owner's durable motion-identity requirement cannot be represented honestly by a visibility ComponentTrack or a paired Role A. Universal skeleton `adventure-studio/universal-skeleton` **1.2.0** remains unchanged. The frozen baseline is a historical source, not a mutable runtime database.

`src/domain/contracts.mjs` owns the typed schema definitions. `npm run schemas` emits 35 record schemas and one bundle schema in `schemas/authoring/1.0.0/`. Every payload has a closed typed object contract; provider configuration and optional `extensions` alone accept bounded JSON values. Unsupported canonical fields must not be hidden in a provider taxonomy. All references bind exact revision UUIDs unless their field explicitly ends `EntityId` or is documented as an internal part/control ID. Entity IDs are logical UUIDv4 identities; immutable revisions have separate UUIDv4 IDs and exact-byte SHA-256 identities in the manifest.

MotionTrack is independent solo performance: canonical joint samples, native FrameObservation references, root/facing, five symbolic expression/gaze channels and an optional exact legacy format4 snapshot hash. It contains no head/kit/garment asset identity. Head/kit selection therefore cannot rewrite body motion. RolePerformance references a MotionTrack. Pose-provider raw topology remains in RawProviderObservation and a separate EvidenceMapping; it never becomes a new skeleton.

The browser runtime validator is a CSP-safe interpreter of this **emitted subset**, not an arbitrary full JSON-Schema implementation. Supported keywords are local `$ref`, `type`, `required`, `properties`, `additionalProperties`, `maxProperties`, `const`, `enum`, `anyOf`, string `minLength`/`maxLength`/`pattern`/UTC `date-time`, numeric `minimum`/`maximum`/`exclusiveMinimum`, and array `items`/`minItems`/`maxItems`/`uniqueItems`. No coercion, remote schema resolution or evaluation occurs. The approved Ajv8.17.1 development dependency compiles every emitted schema as Draft2020-12 and independently checks positive/negative probe equivalence. No Ajv runtime or unsafe-eval enters the browser. A future schema vocabulary addition requires interpreter coverage and equivalence tests before use; arbitrary third-party schemas are not accepted.

Cross-record checks enforce target types, immutable revision ancestry, explicit ownership, rational native time, source/decoder identity, canonical side/joint language, invertible 2D transforms, acyclic layer/part/socket graphs and dimension/byte-length consistency. Rest mesh validation rejects zero/negative triangles, wrong indices, separate-island bridges, constrained hole/boundary/seam crossings and unnormalized skin weights. These are data validity checks, not proof of pose quality or the as-yet-unselected production poser.

Spatial evidence keeps RGBA, binary valid coverage, u8 origin, little-endian u32 contributor indices and contributor sets separately. Set0 is empty. OBSERVED cites visible texture in the designated reference observation; RECOVERED cites a different visible observation plus registration; INFERRED cites a named process. A mixed set conservatively summarizes to INFERRED, then RECOVERED, then OBSERVED. UNKNOWN asserts no supported texture. Texture alpha, provider score, visibility, ownership, reviewer trust and owner acceptance remain distinct.

`AuthoringStore.commit` stages exact record/blob bytes, validates the whole proposed graph and advances heads atomically with compare-and-swap. A failed validation, injected crash or competing commit exposes no new revision/head. Existing revision bytes and the original legacy snapshot cannot be replaced. Independent histories reusing a logical ID need an explicit fork. The new IndexedDB database is `corpus-pane-authoring-v1`; the old database is never opened. An IndexedDB write transaction commits immutable bytes and its bundle head together. It is not yet a multi-device sync protocol.

The portable `.cp-authoring.zip` identifies `corpus-pane/authoring-bundle`1.0.0. Every record/blob/legacy/notice/opaque file is declared with exact length and SHA-256. ZIP CRC, sizes, path collisions/traversal, unsupported features and undeclared files fail closed. The original `.corpus.zip` remains byte-exact under `legacy/original.corpus.zip`; legacy-only export reports the authoring data it cannot carry. Unknown optional record payloads remain hashed opaque bytes. Required unsupported schemas fail. They do not become writable canonical records.

Review claims in JSON do not confer authority. A trusted local actor registry and explicit user-initiated review capability govern new review decisions. Revisions invalidate decision freshness while keeping history. Imported/restored review events retain issuer/status but are historical, inapplicable assertions until locally reassociated. Trusted review reassociation/persistent host identity is deliberately not implemented by an untrusted JSON flag; that integration belongs to the M02 local host. No owner-pending baseline state is promoted.

M01 is a foundation candidate. Browser IndexedDB failure/crash execution, ordinary launcher behavior, source-native PTS intake UI and provider job infrastructure remain M02 independent checks. Family/face/known-anchor/pair final specimen requirements remain blocked as specified in the approved plan. Synthetic validation does not accept FEMALE_STANDARD_V1, a garment, an anchor or a final paired action.
